# Public roadmap — from research to usable infrastructure

This roadmap describes intended delivery milestones, **not committed ship dates**.

## Phase 1 — Evidence-backed foundations

**Historical studies and research milestones**

- [x] Local Ollama Token Reduction Lab controlled measurements.
- [x] Explain/define Necessity, Computational Capital and selective invalidation.
- [x] Compare conditional decision-model execution with ANANKE × JEV bounded experiments.
- [x] Preserve a frozen failed four-arm economic preregistration while documenting positive quality results.
- [x] Develop a versioned local Minimum Admissible Intelligence policy and pass offline-focused tests.

## Phase 2 — Unified native engine acceptance

**Current critical path**

- [x] Correct the identified Windows PGDATA identity-comparison defect and pass focused offline owner and cleanup regressions (not a native runtime PASS).
- [ ] Requalify the repaired identity check during a new, explicitly authorized, isolated native session.
- [ ] Prove a real authenticated request from ingress through Necessity, deterministic/replay or fresh inference, provider admission, validation, Capital and receipts.
- [ ] Prove independently sourced Capital, safe repeated request reuse and selective invalidation with a preserved unrelated control.
- [ ] Reconcile real provider calls, prompt/output tokens, cost models and ANANKE overhead.
- [ ] Capture one coherent M01–M08 native acceptance and independent evidence readback.

## Phase 3 — End-user product acceptance

- [ ] Connect the **existing**, not rebuilt, local Website/BFF to the accepted native engine.
- [ ] Demonstrate authenticated project creation and activation, provider control, governed requests, receipts, reusable knowledge and real usage dashboards.
- [ ] Test denial, isolation, revocation, failures and recovery at the customer boundary.
- [ ] Publish supportable onboarding and API documentation only after those contracts are approved.

## Phase 4 — Research expansion and qualified commercial readiness

- [ ] Test prospectively frozen new workloads and compare total *net* computation advantage.
- [ ] Qualify additional specialized and frontier executor tiers where authorized.
- [ ] Perform independent reproduction with disclosed, rights-cleared fixtures.
- [ ] Complete external security, reliability, hosting, legal/IP and deployment reviews.
- [ ] Gate any private beta or general availability on real end-to-end and operational evidence.

**No roadmap checkbox should be treated as a release announcement.**
