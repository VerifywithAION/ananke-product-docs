# ANANKE CC — Evidence sealing and anti-drift protocol

**Authority:** Public high-level delivery tracking. Product constitution, private engine evidence and current canonical source control outrank this public summary.

## One immutable objective

Complete the pre-existing ANANKE canonical M01–M08 engine, legitimate model-backed Computational Capital lifecycle, usable customer workflow, net resource measurement and authorized domain/hosting deployment. Work on the **earliest unresolved dependency** in `MILESTONES.md`. New research is not a substitute for closing E1–E3.

## Every meaningful change must

1. State the exact milestone ID and its currently unmet predicate. Changes without a milestone dependency are not promoted.
2. Identify owner/source, version and affected integration entry point. Preserve already promoted or historically sealed mechanisms and their verdicts.
3. Use minimal patches, exact byte backups, SHA-256 before/after and focused positive and adversarial negative regressions. No repeat of entire frozen archives without a new defect.
4. Separate `ACTUAL_PROVIDER_MEASURED`, `LOCAL_MODEL_MEASURED`, `OFFLINE_VERIFIED`, `LAB_ONLY_INTEGRATED`, `QUALIFICATION_ONLY`, `CALCULATED`, `PROJECTED`, `NOT_RUN`, `BLOCKED` and `FAIL`.
5. Report calls and tokens **per provider**, model/version, baselines, retries, accuracy/utility, false reuse, false suppression, validator/db/CPU overhead, and economics; if not instrumented use `NOT_MEASURED`.
6. Keep original failed/inconclusive evidence, including Four-Arm R1 economic FAIL. Distinguish scientific acceptance from an engineering/code test PASS.
7. Preserve tenant/project, provenance, source revision, workload call, model digest, receipt identity, independent truth and freshness/contradiction authorization; never make synthetic/QUALIFICATION_ONLY evidence eligible by relabeling.
8. Preserve secrets, private algorithms, customer identifiers, private raw receipts and infrastructure out of this **public** repository.

## Single status rule

`ACCEPTED_IN_SCOPE` requires: documented original preregistered acceptance predicate, authentic run ID, reproducible execution evidence, input/output and source integrity manifest, explicit PASS/FAIL/SKIP, independent validation and negative/security evidence, matched baseline if claiming savings, exact claim boundary, and dated owner approval. Absence of one gate must remain visible. No status inflation from an unrelated component PASS.

A **sealed report** is an append-only `milestones/reports/YYYY-MM-DD-<gate>-<short-name>.md` containing the [template](REPORT_TEMPLATE.md), linked to Git commit/PR and private evidence digest (not private evidence contents). A Git tag or commit SHA gives traceability; do not call it a cryptographic signature unless it was actually signed/verified. Branch/release protection and owner approval must be separately configured and demonstrated.

## GitHub update protocol

- One GitHub delivery epic tracks E0–E6 and R1–R6. Each milestone closes only after its own dated report and approved source/evidence references.
- Progress statuses: `OPEN`, `BLOCKED`, `QUALIFIED_FOR_EXECUTION`, `EVIDENCE_SUBMITTED`, `ACCEPTED_IN_SCOPE`, `SUPERSEDED`. `FAIL` remains an independent recorded result, not renamed PASS.
- Every milestone update links to its original report and approved PR. Do not replace or mutate prior sealed reports; corrections append an amendment with original and new hashes.
- No claim that public docs are automatically synced with private code, GitHub Actions, Notion or hosting. Update explicitly after an accepted milestone; no automation exists until configured.
- The public repository is **not** the owner of private ANANKE source. Any internal details, native runner instructions, implementation diffs, private manifests or secrets belong to an approved private repo/ledger only.
- A product PR must not merge without secure source identity/secret scan, applicable focused regressions, acceptance report, independent reviewer/owner authorization, and explicit release decision.
- Failing a scientific/economic threshold, discovering unsafe reuse or lacking provider/host evidence means `FAIL` or `BLOCKED`, not a revised acceptance threshold.
