# Frequently asked questions

### Is ANANKE an AI model?
No. It is designed as infrastructure that governs whether and how new intelligence should be used. Model providers remain separate executors.

### Is it a semantic cache?
No, although retrieval may supply candidate prior results. A semantic match alone cannot authorize reuse; the result needs valid provenance, scope, dependencies and current applicability.

### Is it a prompt compressor or LiteLLM replacement?
No. Prompt compression may reduce the size of a call. Provider routing may choose among models. ANANKE first asks whether that call is necessary. It can complement those technologies.

### What is Computational Capital?
A validated prior computation whose authority, evidence, dependencies and present applicability support bounded reuse in a later request.

### Does every saved result become Capital?
No. Storing an answer is not the same as earning permission to suppress future inference.

### Will it always reduce token consumption?
No. Benefits depend on workload repetition, real novelty, current source state, available evidence and the cost of governance itself. Some requests must still run full models.

### Are the 193.45× and 24.91× numbers customer guarantees?
Absolutely not. Those were measured reductions in specific earlier local Ollama laboratory workloads.

### Did ANANKE × JEV pass its four-arm scientific trial?
All four arms preserved 240/240 correctness within the benchmark, and the combined arm reduced frontier calls and calculated costs. **The frozen overall Four-Arm R1 verdict was FAIL** because its preregistered economic thresholds were not reached.

### Did ANANKE replace frontier models with JEV?
No. JEV is a specialized bounded decision executor. ANANKE's staged studies tested eligibility and fallback conditions, not universal model replacement.

### Is ANANKE open source?
Not through this repository. This repository contains public educational and product documentation only. Private engine implementation, source contracts and infrastructure remain unpublished.

### Can I install and use the complete product today?
No general-purpose production release or publicly supported installation is represented by this documentation. Unified local-native engine acceptance and a current customer E2E gate are pending.

### Is privacy/security guaranteed?
No system can make such a blanket guarantee. ANANKE's security design includes scoped authorization, fail-closed admissions, protected provider secrets and audit receipts. Production qualification remains separate.

### Why publish failed results?
Because pre-registered thresholds and complete evidence are essential to meaningful research. A useful partial result is not a reason to change the original verdict after seeing the data.

### What is the next concrete milestone?
Complete the single native, authenticated M01–M08 path with real PostgreSQL receipts, legitimate source/Capital transitions, local model usage measurements and safe cleanup; then demonstrate the existing Website/BFF customer journey against that engine.
